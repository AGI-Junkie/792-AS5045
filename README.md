# AS5045 + DRV8825：两连杆绘图臂

CY8CKIT-059（PSoC 5LP，24 MHz）+ 两路 DRV8825；arm1 电机后轴装 AS5045 编码器，arm2 没有编码器。固件用 PSoC Creator 4.4 构建（入口 `DRV8825.cywrk`），上位机是 .NET 10 WPF（`Commissioning/`）。图形（直线、矩形、圆、椭圆、圆弧、圆角矩形、“8”字、正多边形、螺旋、自定义轮廓）在上位机里规划，整条上传后由固件双轴定时插补执行。

## 使用顺序

一键构建并跑全部离线检查（不烧录、不连接串口）：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-release.ps1
```

结果在 `deliverables\<RELEASE_VERSION>\`：`firmware.hex`、完整的 `host\`（不要只拷 exe，需要 .NET 10 Desktop Runtime）、`BUILD_REPORT.txt`、`SHA256SUMS.txt`。

1. 烧录 `firmware.hex` 后上电：两轴保持禁用，约 5 秒静态自检，不自动探测方向、不自动回零。
2. 运行 `host\TwoLinkCommissioning.exe`。只做图形或 XY 预览时无需连接。要控制就选择 KitProg COM 口；连接会先请求停止并释放保持力矩，不会自动使能。
3. 读取输入，逐个检查开关。按 C / “使能”后允许低速点动：A/D 控制 arm1，左右键控制 arm2，松开减速停止。点动只在窗口激活时有效，失焦即释放，回到窗口后要重新按。
4. 建立坐标参考，二选一：
   - **人工确认**（试验阶段的默认做法）：人工把两杆摆成伸直 → 使能 → 点击“人工确认：当前位置为伸直零位”（此姿态记为 q1 = q2 = 0）。
   - **开关回零**：全部松开且静止后按 R / “开始回零”。arm1 在 P0[3] 快碰、退开、慢碰，停稳 50 ms，取 12 个有效编码器角度平均作原点，再走 127° 到伸直位；随后 arm2 对 P1[0] 的 NPN 做同样两次触碰并置零，再向左展开约 163°（36,990 微步）。NPN 装在 arm1 上，回零时两杆内夹角约 20°；163° 含目测追加的 3°，尚未标定。只有收到 `HOME OK` 且 `STATE` 显示 `homed1=1 homed2=1 home=0` 才算成功。
5. 按下节规则填关节范围，低速移到轨迹起点，上传整条轨迹并执行。切窗或最小化时，已启动的回零、起点移动、上传及轨迹执行继续；关闭窗口或断开连接仍请求停止。
6. Space / Esc 在本窗口内任何阶段都能停止（不是系统全局快捷键）。

任何停止（包括通信超时）之后坐标参考都作废，要重新使能，再重新建立参考。原因与恢复方式见 [docs/STATE_MODEL.md](docs/STATE_MODEL.md)。

## 图形

固件不知道图形，只执行上位机检查过的轨迹节点。图形都画在锚点 (X, Y) 周围，再统一做“图形变换”（旋转、缩放、方向）：先绕锚点逆时针旋转，再以锚点为中心缩放，最后决定走向。

| 图形 | X, Y | 尺寸框 | 备注 |
|---|---|---|---|
| 单点 | 目标点 | — | 只移动，不上传 |
| 直线 | 起点 | a, b = 终点 X, Y | 顺时针＝从终点画向起点 |
| 矩形 | 左下角 | a, b = 宽, 高 | 四个角停顿 |
| 圆 | 圆心 | a = 半径 | 起点在圆心右侧 |
| 椭圆 | 中心 | a, b = X 半轴, Y 半轴 | 旋转角就是椭圆长轴方向 |
| 圆弧 | 圆心 | a = 半径，b = 起始角，c = 扫过角度（≤360°） | 顺时针＝向负方向扫 |
| 圆角矩形 | 左下角 | a, b = 宽, 高，c = 圆角半径（≤短边一半） | **一整段连续曲线，四角不停顿**，用来和矩形的尖角停顿对比；起点在底边圆角之后 |
| “8”字 / 利萨如 | 中心 | a, b = 宽、高半幅，c = Y 向频率比（整数 2～6，2＝“8”字） | 横着的 8；旋转 90° 得到竖的 8 |
| 正多边形 | 中心 | a = 外接圆半径，b = 边数（3～12，3＝三角形） | 每个顶点停顿 |
| 螺旋 | 中心 | a, b = 起、止半径，c = 圈数（≤20） | 开放曲线，不回到起点 |
| 自定义轮廓 | 轮廓原点 | 文本框 | 每行一个点“x y”（mm），或一条 SVG 路径（M L H V C S Q T Z，y 向下已翻转） |

自定义轮廓只支持**一条连续路径**：机器没有抬笔，多个独立轮廓（含文字）之间会留下连接线，所以两条以上的轮廓会被拒绝。点列里每个点都是停顿角；SVG 里的曲线被拆成约 1 mm 的小段，只在明显转折处（>25°）停顿，其余连续走过。不支持 SVG 的弧命令 A。

所有图形共用同一套检查：每个采样点（≤1 mm）、采样点之间、量化后的每个节点都要落在 q1、q2、肘三个范围内。直线、矩形、多边形和圆用精确极值；曲线在每个 1 mm 间隔内再查三个点（约 0.25 mm 一个），所以曲线的边界判断有约 0.01° 量级的余量误差。

## 坐标与关节范围

- **arm1**：42 电机接 stepper2，1.8° 整步、1/8 微步、40:1 减速；AS5045 在电机后轴，使用多圈累计（输出转 9° 就是电机转一圈）。P0[3] 开关触点为零；伸直后不再次清零，所以回零后显示约 ±127°，符号取决于实测编码器方向。
- **arm2**：Anaheim `11YPG302S-LW4-R51` 接 stepper1，1.8°、减速比 51.06:1、1/8 微步，按输出轴直接驱动关节计算。NPN 触点是指令零点，伸直后计数为 −36,990。没有编码器，`commanded usteps` 不是实测角度。
- 静态自检通过只说明编码器帧和 GPIO 电平符合要求，不能证明 VMOT 有电、电机转动、传感器接线正确或输出轴定位精度。编码器失效不会降级为开环继续运动。回零成功不等于完成精度标定；AS5045 在电机侧，测不到减速箱回差。

### 关节范围填写规则（absolute-q2 固件起）

q1、q2 都是相对固定 +X 的连杆**绝对**角，肘（电机 2）转过的角度是 q2 − q1（伸直为 0，向左为正；NPN 回零点在右侧约 −163°，左侧没有开关）。界面里 q2 的最小/最大限制的是连杆 2 的朝向，**不限制肘**；肘有自己的“肘 最小 / 最大”两个框，三组范围（q1、q2、肘）同时生效：

| 环节 | 怎么用肘范围 |
|---|---|
| 预览、红区（可达区域） | 姿态必须同时落在 q1、q2、肘三个范围内，逆解两支里不满足的会被红区挡掉 |
| 轨迹规划、执行计划、上传前复核 | 每个采样点、采样点之间的极值（圆在离基座最近/最远处）、量化后的每个节点都检查；越界时提示的是哪一个范围 |
| 单点移动 | 目标姿态在设备确认的三个范围内才允许 |
| 固件 | PTP 单点、轨迹 BEGIN/NODE 的 q2 − q1 必须在范围内；当前位置在范围外时拒绝新的 PTP；运动中越界立即停止；点动到肘边界不再向外 |

肘范围和 q1/q2 范围一样，在未使能时同步给固件，设备确认后才允许运动；已使能时修改要先总停止。姿态读数行显示当前肘角和到两侧边界的余量（负数表示已越界）。

**肘范围还没有实测**：默认 ±155°（沿用旧版肘限位，固件开机值相同），不是实测机械行程。用手慢慢推两侧到机械挡点（或线缆/碰撞开始受力处），量出角度后，把“肘 最小 / 最大”填成略小于它的值。机械行程的实测记录请写在这里。

选范围时可参考：肘最小 = q2 最小 − q1 最大、肘最大 = q2 最大 − q1 最小 是两个 q 框**允许**的最大肘范围，肘框把它收窄到真正安全的部分。例（肘 ±155°）：

- 只画 x 260…340 mm、|y| ≤ 50 mm（连杆 180 / 176.38 mm，取肘 > 0 的解，需要 q1 约 −53…−7°、q2 约 +7…+54°，肘约 30…65°）：q1 [−60, 5]、q2 [−5, 60]，肘 [−10, 120] 已足够。

开机默认 q1 ±30°、q2 ±60°、肘 ±155°。上位机启动会载入 `%LOCALAPPDATA%\TwoLinkCommissioning\parameters.json` 里保存的范围并在连接后同步给固件；旧版保存的文件没有肘范围，按默认 ±155° 载入——这也让 2026-09-29 保存的 q1 ±140°、q2 ±155°（原先肘可达 ±295°）不再放行超出肘范围的位姿。

## 保护与调试参数

回零是非阻塞状态机。两轴的快碰和慢碰都持续搜索，直到各自回零开关触发，**没有搜索步数或时间上限**（开关失效时只能靠操作者或其他保护停止）；整个流程持续接收串口，监测编码器、nFAULT、全局限位和 250 ms 心跳。释放、退开和伸直阶段仍有行程与时间上限。无通信、按停止、回零期间按点动键、编码器失效、跟随误差过大均停止，不自动恢复。

原始停止字节 `0x79`（含主机关闭/断连时的停止请求）让两轴驱动**断电**，释放保持力矩；固件自身的通信超时、限位和编码器保护停止**保持通电**；nFAULT 使驱动断电。所有停止都作废坐标参考。

`main.c` 顶部的可调参数：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `JOG1_RATE_MAX_USTEP_S` | 800 | arm1 低速验收，4.5 输出度/秒 |
| `JOG2_RATE_MAX_USTEP_S` | 600 | arm2 低速验收 |
| （无固定值） | 全局速度 | 回零快碰和走到伸直位按界面设置的全局速度和加速度（`g_motionRate` / `g_motionAccel`），不再有固定的 600/800 上限；机械上能否承受这个速度要自己把握 |
| `HOME_RELEASE_RATE_USTEP_S` | 600 | 回零释放 / 退开速率，沿用较低的点动速度上限（全局速度更低时取全局） |
| `HOME_SLOW_RATE_USTEP_S` | 400 | 二次触碰上限（全局速度更低时取全局速度） |
| `HOME_ZERO_SAMPLES` / `HOME_ZERO_SAMPLE_MS` | 12 / 1 ms | arm1 停稳后平均采样次数 / 最小间隔 |
| `HOME_ACCEL_USTEP_S2` | 4000 | 释放、退开、慢碰的加减速上限（快碰和走到伸直位用全局加速度） |
| `HOME_BACKOFF_USTEPS` | 64 | 释放传感器后的额外退开 |
| `HOME_RELEASE_MAX_USTEPS` | 800 | 传感器必须释放的最大行程 |
| `HOME_PHASE_TIMEOUT_MS` | 120000 | 释放、退开、停稳及伸直阶段的时间上限（不用于快碰/慢碰搜索） |
| `ARM1_STRAIGHT_OUT_DEG10` | 1270 | 开关到伸直位 127.0°，需实机确认 |
| `ARM2_STRAIGHT_OUT_DEG10` | 1630 | NPN 到伸直位 163.0°，按实际姿态微调 |
| `ARM2_STRAIGHT_JOG_DIR` | −1 | 用户确认：向左展开 |
| `ARM2_MOTOR_FULLSTEPS_REV` / `ARM2_GEAR_RATIO_X100` | 200 / 5106 | arm2 独立传动参数 |

两轴物理左转均为 DIR = 0。编码器极性在人工启动回零后的实际运动中识别，无需上电试走；极性尚未识别时，点动不执行依赖极性的闭环保持和软限位，其余保护仍在。

## 构建与离线检查

GitHub Actions 的 `Host CI` 在上位机源码或工作流变更的 PR、`main` 推送时运行，也支持手动触发。它使用 Windows / .NET 10 发布上位机并运行现有 `--self-test`；日志、离线截图和规划数据保存为 `host-ci-diagnostics`，保留 14 天。该工作流不构建固件、不连接串口。

`build-release.ps1` 依次做：Creator 构建固件 → `verify-creator-pins.ps1`（TopDesign 与 `main.c` 的引脚一致）→ 发布上位机 → 上位机 `--self-test`（含真实 WPF 调度回放，UI 租约间隔 ≥ 200 ms 判失败）→ 固件 C 测试 → 源码哈希前后比对 → `BUILD_REPORT.txt` / `SHA256SUMS.txt`。构建过程中改动被哈希的源文件会中止并报错。

单独运行：

```powershell
python tests\test_stage1.py                 # 全部固件 C 用例（需要 Visual Studio C++ 工具，默认路径见脚本）
python tests\test_stage1.py fuzz_3          # 只跑一个随机种子；失败时打印种子与步号，可复现
python tests\test_stage1.py --emit-c=DIR    # 只生成 check.c，便于调试或长时间 fuzz
python tools\check-log.py --self-test
```

固件 C 测试编译**未经修改**的 `main.c`，把 GPIO、SysTick、编码器（引脚级）和 UART API 换成模拟，跑真实的前台循环片段；`fuzz_*` 用随机事件序列逐毫秒检查状态不变量。它验证控制流，不验证真实 UART 时序、电机力矩或传感器接线。
