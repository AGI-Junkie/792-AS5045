# AS5045 + DRV8825：两连杆绘图臂

CY8CKIT-059（PSoC 5LP，48 MHz）+ 两路 DRV8825；两轴电机后轴装 AS5045，当前默认 `ARM2_ENCODER_FEEDBACK=1`，要求双编码器有效。固件默认使用硬件 SSI、STEP PWM 和轨迹事件中断。固件用 PSoC Creator 4.4 构建（入口 `DRV8825.cywrk`），上位机是 .NET 10 WPF（`Commissioning/`）。图形（直线、矩形、圆、椭圆、圆弧、圆角矩形、“8”字、正多边形、螺旋、自定义轮廓）在上位机里规划，整条上传后由固件双轴定时插补执行。

## 使用顺序

一键构建并跑全部离线检查（不烧录、不连接串口）：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-release.ps1
```

**最新可用的上位机固定在 `out\latest\host\TwoLinkCommissioning.exe`**（每次闸门全过后自动覆盖，版本见同目录 `BUILD_REPORT.txt` 第一行；闸门失败则保持上一版不动）。各版本另存于 `out\<RELEASE_VERSION>\`：`firmware.hex`、完整的 `host\`（不要只拷 exe，需要 .NET 10 Desktop Runtime）、`BUILD_REPORT.txt`、`SHA256SUMS.txt`。

1. 烧录 `firmware.hex` 后上电：两轴保持禁用，约 5 秒静态自检，不自动探测方向、不自动回零。
2. 运行 `host\TwoLinkCommissioning.exe`。只做图形或 XY 预览时无需连接。要控制就选择 KitProg COM 口；连接会先请求停止并释放保持力矩，不会自动使能。
3. 读取输入，逐个检查开关。按 C / “使能”后允许低速点动：A/D 控制 arm1，左右键控制 arm2，松开减速停止。点动只在窗口激活时有效，失焦即释放，回到窗口后要重新按。
4. 建立坐标参考，可选择正常开关回零或人工伸直确认。
   - **人工确认**：可人工把两杆摆成伸直，再点击“人工确认：当前位置为伸直零位”（此姿态记为 q1 = q2 = 0）。默认配置要求两路编码器有效；arm2 方向尚未被回零识别时，人工确认使用台架标定方向 `MANUAL_ENC2_INC_DIR=1`，回零后使用实测方向。重新使能会清除方向识别；该台架方向仍需在实际安装上核对。
   - **开关回零**：全部松开且静止后按 R / “开始回零”。arm1 在 P0[3] 快碰、退开、慢碰，停稳 50 ms，取 12 个有效编码器角度平均作原点，再走 126° 到伸直位；随后 arm2 对 P1[0] 的 NPN 做同样两次触碰并置零，再向左展开 162°（36,763 微步）。NPN 装在 arm1 上，回零时两杆内夹角约 20°；126°/162° 是当前源码配置，尚需正式标定。两轴均在回零运动中识别方向并检查编码器。只有收到 `HOME OK` 且 `STATE` 显示 `homed1=1 homed2=1 home=0` 才算成功。
5. 按下节规则填关节范围，低速移到轨迹起点，上传整条轨迹并执行。切窗或最小化时，已启动的回零、起点移动、上传及轨迹执行继续；关闭窗口或断开连接仍请求停止。
6. Space / Esc 在本窗口内任何阶段都能停止（不是系统全局快捷键）。

任何停止（包括通信超时）之后坐标参考都作废，要重新使能，再重新建立参考。原因与恢复方式见 [docs/STATE_MODEL.md](docs/STATE_MODEL.md)。

## 界面怎么用：操作流程条、方案、参数状态

- **操作流程条**（工具栏下面一行）：连接 → 使能 → 建立参考 → 检查轨迹 → 移到起点 → 上传 → 执行 → 查看结果。每步显示 ✓ 已完成、● 当前、○ 未到、– 本图形不需要（单点没有上传和执行）；第一个没完成的步骤下面一行写“下一步”：能做就写怎么做，暂时不能做就写具体原因（例如“范围与设备不一致，先总停止”“设备还不在起点”）。鼠标停在每一格上看这一步的详细状态。检查轨迹不依赖设备，所以离线时它也可以是 ✓。
- **方案**（左侧第一组）：小圆演示、直线测试、重复定位实验（单点），也可以把当前的图形、尺寸、变换和速度“另存为…”成自己的方案。选择方案**只载入并检查，不会运动**，运动仍要点“移到起点 / 上传 / 执行”；方案不包含杆长和关节/肘范围（那是机器的设置，改了需要总停止并重新同步）。自己的方案存在 `%LOCALAPPDATA%\TwoLinkCommissioning\presets.json`。
- **参数状态灯**（图形、变换、机构尺寸、关节范围、运动参数每组的第一行）：● 已保存到电脑（与 `parameters.json` 一致）/ ○ 未保存；● 设备已确认 / ○ 设备未确认（范围和速度分开判断，所以改速度之后能看出是速度还在同步，而不是范围）；● 已用于上传的图形 / ○ 与设备上的图形不同（改了参数后要重新上传才生效）/ – 设备上没有图形。

## 实验分析与回放

“实时反馈与实验”页里的“实验分析与回放…”打开一个独立窗口，读取 `%LOCALAPPDATA%\TwoLinkCommissioning\Experiments\` 里已经保存的实验（旧版本的也能读）：

- **列表**：开始时间、类型、图形、速度（电机1/2）、参考方式、完成情况（完整 / 记录中断 / 中止原因）、RMSE、峰值、遥测速率、当时的标定版本、是否有停机快照。点选一次实验看曲线；按住 Ctrl 再点选另一次**叠加比较**（最多两次，颜色 A 蓝、B 橙，摘要给出 RMSE/峰值/时长的相对变化——同一图形比较才有意义）。“导出列表 CSV”把整张表连同每次的“计划与记录对齐”检查结果导出，命令行也可以：`TwoLinkCommissioning.exe --experiments-report <实验目录> <输出.csv>`。
- **曲线**（共用一条时间轴，0 = 计划起点）：arm1 角度（命令 / 编码器 / 规划）；arm1 误差＝编码器−命令（±RMSE 虚线，起步/拐角/停机事件竖线，有停机快照时标出故障时刻）；规划速度和规划加速度（电机2 转的是肘角 q2−q1），每个电机的设定上限画成虚线，摘要写出哪个电机接近上限，**没有电机到上限就如实说**（计划还会被脉冲/弦误差检查放慢）。
- **XY 平面**：规划轨迹、指令估算、编码器模型估算（当前默认取双编码器；旧记录或显式关闭 arm2 反馈的构建保留 arm1 编码器加 arm2 指令的混合来源）三条线和回放时刻的连杆姿态。**XY 全部是模型估算，不是实测笔尖位置**；两轴反馈均在电机侧，看不到减速箱回差。每张图下面都写着数据来源。
- **回放**：拖时间轴、点曲线或按“回放”（0.5×–5×），四张曲线的游标、连杆姿态、图例里每条曲线此刻的值、以及下面“此刻前后 1 秒的连接日志”一起动。日志取自当时那次连接的日志文件（按开始时间匹配，可隐藏状态块）。
- **计划与记录怎么对上**：遥测是设备时钟，计划从 0 起算；窗口用“指令走的就是计划”这一点，在设备时钟上平移计划，找指令与计划最吻合的位置（真实记录上残差约 0.005°，2 Hz 遥测也行）。残差大于 1° 时摘要会警告标记仅供参考。

## 标定向导（测量记录）

“实时反馈与实验”页里的“标定向导…”打开一个独立窗口，把**测量**记成一份带日期和版本号的标定文件，位置 `%LOCALAPPDATA%\TwoLinkCommissioning\Calibrations\cal-<日期时间>-v<版本>.json`（只增不改；`active.txt` 指向“当前标定”）。**它不会改变机器，也不做补偿**：先测，数据出来再决定补不补、怎么补。六步，每步可以只填一部分，至少填一节才能保存：

1. **杆长**：卡尺/尺子/CAD 量的 L1、L2、测量方法和不确定度。输入框一开始是空的（规划现在用的杆长不是测量值）；下面显示和规划杆长的差。“采用为规划杆长”只把这两个数填进规划参数的杆长框，预览随之按新杆长重新规划；设备上已经上传的旧图形和新参数不再一致（参数灯显示“与设备上的图形不同”），需要重新上传。
2. **回零后的真实姿态**：参考建立方式（读自设备）、q1/q2 零位偏差、实测笔尖 X/Y（可选）、备注。全 0 又没写别的，当作“没测”。
3. **机械行程**：慢速点动到机械挡点后点“读取当前位置”，取设备的指令角（肘＝q2−q1；此标定页面仍使用**指令角**，双电机轴编码器不能直接测输出轴回差，挡点处堵转时实际更小）。给出“离挡点内缩 N°”的建议范围，“采用为肘范围”只把它填进规划参数的肘范围框，再由上位机同步给设备（已使能时需先总停止）。这是量出 ±155° 默认值是否合适的办法。
4. **正反向重复定位**：选一个目标点和趋近角 δ，生成“+、−、+、−……”交替的试验表（交替，免得慢漂移被当成回差）。每行：“移到预备点”（目标 q1 ± δ）→ 等停稳 → “移到目标”→ 等停稳 → “记录这次到位”（读设备的 q1/q2 指令和 arm1 编码器角）→ 用尺子/千分表把笔尖 X、Y 填进表。移动走和主窗口“移动”按钮同一道闸（已使能、已建参考、反馈新鲜、范围已确认、没有别的在跑）。统计：每个方向的 σx、σy、最大散布；**回差**＝两个方向平均位置沿趋近方向的差；**单向重复性**＝两个方向中较大的最大散布。arm1 编码器在电机侧，看不到减速箱回差，所以回差要靠笔尖实测。
5. **总结与保存**：摘要（固件、参考、版本号）和备注；保存成新版本，并成为当前标定。
6. **已保存的标定**：历史列表，“设为当前标定”可以切换，“打开标定文件夹”。

之后每次实验的 `metadata.json` 记下当时的 `calibration_id`；实验列表多一列“标定”（v1、v2……；旧记录显示 —），摘要写出完整编号，导出的 CSV 有 `calibration_id` 列，用来比较标定前后的实验。

## 图形

固件不知道图形，只执行上位机检查过的轨迹节点。参数图形画在锚点 (X, Y) 周围，再统一做“图形变换”（旋转、缩放、方向）：先绕锚点逆时针旋转，再以锚点为中心缩放，最后决定走向。手绘直接使用画布世界坐标，不应用这些变换。

| 图形 | X, Y | 尺寸框 | 备注 |
|---|---|---|---|
| 单点 | 目标点 | — | 只移动，不上传 |
| 直线 | 起点 | a, b = 终点 X, Y | 顺时针＝从终点画向起点 |
| 矩形 | 左下角 | a, b = 宽, 高 | 四个角停顿 |
| 圆 | 圆心 | a = 半径 | 起点在圆心右侧 |
| 椭圆 | 中心 | a, b = X 半轴, Y 半轴 | 旋转角就是椭圆长轴方向 |
| 圆弧 | 圆心 | a = 半径，b = 起始角，c = 扫过角度（≤360°） | 顺时针＝向负方向扫 |
| 圆角矩形 | 左下角 | a, b = 宽, 高，c = 圆角半径（≤短边一半） | **一整段连续曲线，四角不停顿**，用来和矩形的尖角停顿对比；起点在底边圆角之后 |
| “8”字 / 利萨如 | 中心 | a, b = 宽、高半幅，c = Y 向频率比（整数 2～6，2＝“8”字） | 横着的 8；旋转 90° 得到竖的 8 |
| 正多边形 | 中心 | a = 外接圆半径，b = 边数（3～12，3＝三角形） | 每个顶点停顿 |
| 螺旋 | 中心 | a, b = 起、止半径，c = 圈数（≤20） | 开放曲线，不回到起点 |
| 自定义轮廓 | 轮廓原点 | 文本框 | 每行一个点“x y”（mm），或一条 SVG 路径（M L H V C S Q T Z，y 向下已翻转） |
| 手绘 | 画布世界坐标 | 左键绘制 | 末端吸附续画；连续三次样条，草稿到曲线偏差 ≤1 mm；[使用与验收](docs/FREEHAND_TRAJECTORY.md) |

自定义轮廓只支持**一条连续路径**：机器没有抬笔，多个独立轮廓（含文字）之间会留下连接线，所以两条以上的轮廓会被拒绝。点列里每个点都是停顿角；SVG 里的曲线被拆成约 1 mm 的小段，只在明显转折处（>25°）停顿，其余连续走过。不支持 SVG 的弧命令 A。

所有图形共用同一套检查：每个采样点（≤1 mm）、采样点之间、量化后的每个节点都要落在 q1、q2、肘三个范围内。直线、矩形、多边形和圆用精确极值；曲线在每个 1 mm 间隔内再查三个点（约 0.25 mm 一个），所以曲线的边界判断有约 0.01° 量级的余量误差。

## 坐标与关节范围

- **arm1**：42 电机接 stepper2，1.8° 整步、1/8 微步、40:1 减速；AS5045 在电机后轴，使用多圈累计（输出转 9° 就是电机转一圈）。P0[3] 开关触点为零；伸直后不再次清零，所以回零后显示约 ±126°，符号取决于实测编码器方向。
- **arm2**：Anaheim `11YPG302S-LW4-R51` 接 stepper1，1.8°、减速比 51.06:1、1/8 微步，按输出轴直接驱动关节计算。NPN 触点用双次触碰和编码器平均建立零点，当前伸直配置的指令计数为 −36,763。第二块 AS5045 测电机后轴；累计转数经 51.06:1 换算为肘角。q2 实测值 = q1 实测值 + 肘角。
- 静态自检通过只说明编码器帧和 GPIO 电平符合要求，不能证明 VMOT 有电、电机转动、传感器接线正确或输出轴定位精度。编码器失效不会降级为开环继续运动。回零成功不等于完成精度标定；AS5045 在电机侧，测不到减速箱回差。

### 关节范围填写规则（absolute-q2 固件起）

q1、q2 都是相对固定 +X 的连杆**绝对**角，肘（电机 2）转过的角度是 q2 − q1（伸直为 0，向左为正；当前配置把 NPN 回零点放在右侧 −162°，左侧没有开关）。界面里 q2 的最小/最大限制的是连杆 2 的朝向，**不限制肘**；肘有自己的“肘 最小 / 最大”两个框，三组范围（q1、q2、肘）同时生效：

| 环节 | 怎么用肘范围 |
|---|---|
| 预览红区（连杆边界） | 每侧以范围内的极限姿态连接基座→肘点→笔尖，再沿第二段直线延伸至最大伸展圆，按直线边界填红。它是连杆边界参考，留白不保证笔尖可达或无碰撞；鼠标另示精确笔尖逆解结果 |
| 轨迹规划、执行计划、上传前复核 | 每个采样点、采样点之间的极值（圆在离基座最近/最远处）、量化后的每个节点都检查；越界时提示的是哪一个范围 |
| 单点移动 | 目标姿态在设备确认的三个范围内才允许 |
| 固件 | PTP 单点、轨迹 BEGIN/NODE 的 q2 − q1 必须在范围内；当前位置在范围外时拒绝新的 PTP；运动中越界立即停止；点动到肘边界不再向外 |

肘范围和 q1/q2 范围一样，在未使能时同步给固件，设备确认后才允许运动；已使能时修改要先总停止。姿态读数行显示当前肘角和到两侧边界的余量（负数表示已越界）。

**肘范围还没有实测**：默认 ±155°（沿用旧版肘限位，固件开机值相同），不是实测机械行程。用手慢慢推两侧到机械挡点（或线缆/碰撞开始受力处），量出角度后，把“肘 最小 / 最大”填成略小于它的值。机械行程的实测记录请写在这里。

选范围时可参考：肘最小 = q2 最小 − q1 最大、肘最大 = q2 最大 − q1 最小 是两个 q 框**允许**的最大肘范围，肘框把它收窄到真正安全的部分。例（肘 ±155°）：

- 只画 x 260…340 mm、|y| ≤ 50 mm（连杆 180 / 176.38 mm，取肘 > 0 的解，需要 q1 约 −53…−7°、q2 约 +7…+54°，肘约 30…65°）：q1 [−60, 5]、q2 [−5, 60]，肘 [−10, 120] 已足够。

开机默认 q1 ±30°、q2 ±60°、肘 ±155°。上位机启动会载入 `%LOCALAPPDATA%\TwoLinkCommissioning\parameters.json` 里保存的范围并在连接后同步给固件；旧版保存的文件没有肘范围，按默认 ±155° 载入——这也让 2026-09-29 保存的 q1 ±140°、q2 ±155°（原先肘可达 ±295°）不再放行超出肘范围的位姿。

## 保护与调试参数

回零是非阻塞状态机。两轴的快碰和慢碰都持续搜索，直到各自回零开关触发，**没有搜索步数或时间上限**（开关失效时只能靠操作者或其他保护停止）；整个流程持续接收串口，监测编码器、nFAULT、全局限位和 250 ms 心跳。释放、退开和伸直阶段仍有行程与时间上限。无通信、按停止、回零期间按点动键、编码器失效、跟随误差过大均停止，不自动恢复。

原始停止字节 `0x79`（含主机关闭/断连时的停止请求）让两轴驱动**断电**，释放保持力矩；固件自身的通信超时、限位和编码器保护停止**保持通电**；nFAULT 使驱动断电。所有停止都作废坐标参考。

`main.c` 顶部的可调参数：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| `JOG1_RATE_MAX_USTEP_S` | 800 | arm1 低速验收，4.5 输出度/秒 |
| `JOG2_RATE_MAX_USTEP_S` | 600 | arm2 低速验收 |
| （无固定值） | 全局速度 | 回零快碰和走到伸直位按界面设置的全局速度和加速度（`g_motionRate` / `g_motionAccel`），不再有固定的 600/800 上限；机械上能否承受这个速度要自己把握 |
| `HOME_RELEASE_RATE_USTEP_S` | 600 | 回零释放 / 退开速率，沿用较低的点动速度上限（全局速度更低时取全局） |
| `HOME_SLOW_RATE_USTEP_S` | 400 | 二次触碰上限（全局速度更低时取全局速度） |
| `HOME_ZERO_SAMPLES` / `HOME_ZERO_SAMPLE_MS` | 12 / 1 ms | arm1 停稳后平均采样次数 / 最小间隔 |
| `HOME_ACCEL_USTEP_S2` | 4000 | 释放、退开、慢碰的加减速上限（快碰和走到伸直位用全局加速度） |
| `HOME_BACKOFF_USTEPS` | 64 | 释放传感器后的额外退开 |
| `HOME_RELEASE_MAX_USTEPS` | 800 | 传感器必须释放的最大行程 |
| `HOME_PHASE_TIMEOUT_MS` | 120000 | 释放、退开、停稳及伸直阶段的时间上限（不用于快碰/慢碰搜索） |
| `ARM1_STRAIGHT_OUT_DEG10` | 1260 | 开关到伸直位 126.0°，需实机确认 |
| `ARM2_STRAIGHT_OUT_DEG10` | 1620 | NPN 到伸直位 162°，按实际姿态微调 |
| `ARM2_STRAIGHT_JOG_DIR` | −1 | 用户确认：向左展开 |
| `ARM2_MOTOR_FULLSTEPS_REV` / `ARM2_GEAR_RATIO_X100` | 200 / 5106 | arm2 独立传动参数 |

两轴物理左转均为 DIR = 0。编码器极性在人工启动回零后的实际运动中识别，无需上电试走；极性尚未识别时，点动不执行依赖极性的闭环保持和软限位，其余保护仍在。

## 构建与离线检查

GitHub Actions 的 `Host CI` 在上位机源码或工作流变更的 PR、`main` 推送时运行，也支持手动触发。它使用 Windows / .NET 10 发布上位机并运行现有 `--self-test`；日志、离线截图和规划数据保存为 `host-ci-diagnostics`，保留 14 天。该工作流不构建固件、不连接串口。

`build-release.ps1` 依次做：Creator 构建固件 → `verify-creator-pins.ps1`（TopDesign 与 `main.c` 的引脚一致）→ 发布上位机 → 上位机 `--self-test`（含真实 WPF 调度回放，UI 租约间隔 ≥ 200 ms 判失败）→ 固件 C 测试 → 源码哈希前后比对 → `BUILD_REPORT.txt` / `SHA256SUMS.txt`。构建过程中改动被哈希的源文件会中止并报错。

单独运行：

```powershell
python tests\test_stage1.py                 # 全部固件 C 用例（需要 Visual Studio C++ 工具，默认路径见脚本）
python tests\test_stage1.py fuzz_3          # 只跑一个随机种子；失败时打印种子与步号，可复现
python tests\test_stage1.py --emit-c=DIR    # 只生成 check.c，便于调试或长时间 fuzz
python tools\check-log.py --self-test
```

固件 C 测试编译**未经修改**的 `main.c`，把 GPIO、SysTick、编码器（引脚级）和 UART API 换成模拟，跑真实的前台循环片段；`fuzz_*` 用随机事件序列逐毫秒检查状态不变量。它验证控制流，不验证真实 UART 时序、电机力矩或传感器接线。

### 日志级别

上位机日志页可选择最低级别，默认 Info：Trace 为逐帧遥测，Debug 为状态/协议诊断，Info 为操作事件，Warning 为拒绝指令/重试/通信间隔警告，Error 为停机证据、故障与超时。故障状态优先于普通状态分级；未知固件文本默认 Info。主机错误调用显式指定级别。

筛选只影响界面，协议解析、实验 CSV 和原始连接日志仍完整保留；切换级别重绘最近 1000 行，更早记录查看 `%LOCALAPPDATA%\TwoLinkCommissioning\Logs`。实验回放的“隐藏状态块”复用同一分级规则，显示 Info 及以上。固件 UART 承载协议，因此不通过日志级别关闭它。

验证：`TwoLinkCommissioning.exe --log-level-self-test`，以及 `--language-self-test`。
