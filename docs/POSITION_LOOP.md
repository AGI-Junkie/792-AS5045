# 电机轴位置闭环：架构、技术与制作过程

最后更新 2026-11-21。本文同时是设计说明和制作过程记录：每个决定都写了当时的问题、考虑过的做法，以及为什么这样选。

- 代码：[posloop.h](../DRV8825.cydsn/posloop.h)，接入点在 [main.c](../DRV8825.cydsn/main.c)（搜 `POS_LOOP`）
- 仿真用例：[tests/test_stage1.py](../tests/test_stage1.py)（搜 `posloop`）

**状态：`POS_LOOP=1` 已是默认构建，仿真全部通过；没有烧录，也没有台架验证。** 所有增益和窗口都是起始值，不是整定结果。

## 1. 一句话

把两轴步进机械臂从“**按计划发脉冲、编码器只负责报警**”改成“**按时间生成参考、编码器把电机拉回参考**”。硬件、上位机和通信协议都不变。

> 线性插补负责算目标，编码器反馈负责把电机拉回目标。

## 2. 范围

| 做了 | 没做 |
|---|---|
| 轨迹 RUN（绘图）闭环 | 输出轴或笔尖闭环（减速箱回差在环外） |
| 单点 PTP 移动闭环（梯形时间律参考） | 积分项 |
| 运动结束后的终点保持和到点判定 | 到点之后的长期保持（之后仍只保持驱动器通电） |
| 跟踪误差停机、保持超时停机 | 点动和回零（保持原来的开环方式，点动有原来的补步保持） |

硬件：PSoC 5LP（Cortex-M3，48 MHz）、两路 AS5045 磁编码器（装在电机轴上，4096 LSB/圈，硬件 SSI 菊花链读取）、两片 DRV8825（1/8 微步，1600 微步/圈）。减速比 40:1 和 51.06:1。

## 3. 架构

```
┌─────────────── 上位机（C# / .NET 10 WPF，不变）───────────────┐
│ 逆运动学 → 五次多项式时间规划 → 带时长的节点 (q1, q2, ms)      │
│ 上传前校验：弦长误差、每轴速度、段间加速度                     │
└──────────────────────────────┬────────────────────────────────┘
                               │ UART/USB，协议 proto=6（不变）
┌──────────────────────────────┴──────── PSoC 5LP 固件 ─────────┐
│ 前台循环（1 kHz）                                            │
│   硬件 SSI 读双 AS5045 → 多圈累计 → lag[i] = 指令 − 实测（步） │
│   心跳、限位、nFAULT、关节范围、到点判定、计数器重新对齐       │
│                                                              │
│ EvtTimer 中断（10 kHz，优先级 1）                             │
│   ① 参考：轨迹 = 节点间线性插补；PTP = 梯形时间律              │
│   ② 每 1 ms：e = (ref − cmd) + lag − v·τ                      │
│             v = 限幅(v_ff + 限幅(Kp·e))                        │
│   ③ 每轴相位累加器：acc += v·dt，满一步 → STEP/DIR             │
│                                                              │
│ UDB 硬件：一次性 PWM 产生 STEP 脉冲；引脚中断直接关断 PWM       │
└──────────────────────────────────────────────────────────────┘
```

分层：

| 层 | 技术 | 本项目里的做法 |
|---|---|---|
| 轨迹规划 | C# WPF、逆运动学、五次多项式时间规划 | 上位机生成带时长的节点，五次多项式决定沿路径怎么加减速（[TimedTrajectory.cs](../Commissioning/TimedTrajectory.cs)） |
| 参考生成 | 共用轨迹时钟、分段线性插补、梯形时间律 | 中断按当前时间求两轴参考位置和速度；第二轴用独立肘角 q2 − q1 换算（`traj_joint_steps`） |
| 反馈与控制 | 嵌入式 C、硬件 SSI、多圈计数、速度前馈 + 比例反馈 | 误差拆成“精确的开环部分 + 实测滞后”；四道限幅；带回差的死区 |
| 实时发步 | 定时器中断、每轴相位累加器（NCO）、UDB PWM | 每轴独立调速，替换掉两轴步数比例锁死的 DDA；复用原有脉冲输出和全部保护 |
| 验证 | 整机 C 仿真（真实 `main.c` + 模拟外设） | 开环和闭环两套构建分别回归；丢步、卡死、终点受扰、双轴绘图用例 |

## 4. 原来的系统和它的局限

原来的轨迹执行器（[traj.h](../DRV8825.cydsn/traj.h)）是**开环双轴 DDA**：

- 每个节点算出两轴目标步数，用 Bresenham 式 DDA 按固定比例分配脉冲；
- 第 k 步在 k × 时长 / 总步数 时刻发出；
- 编码器只**检查**：跟随误差 ≥ 328 LSB 就停机，到点误差 > 228 LSB 也停机。

局限：

- 丢了几步，机器照样走完，终点就差这几步；
- DDA 让两轴步数严格成比例，没法只给一个轴提速补回来。

PTP 单点移动用的是 AVR446 梯形加减速（每步算下一个间隔），问题一样。

## 5. 关键设计决定（以及为什么）

### 5.1 参考从“步数分配”改成“时间的函数”

开环回答的是“下一步什么时候发”，闭环要回答的是“现在应该在哪”。

- **轨迹**：节点 k 内 `ref = from + (to − from) · t / T`，斜率就是速度前馈。两轴读同一个时钟，所以天然同步。
- **PTP**：沿步数空间的直线走梯形时间律，以较长的那个轴为准：
  - 加速段 `s = a·t²/2`，匀速段 `s = R²/2a + R·(t − Ta)`，减速段对称；
  - 距离太短时退化成三角形，峰值速度取 `√(a·D)`，总时长仍是 `T = D/R + R/a`；
  - 另一轴按比例跟随，所以 PTP 仍然是两轴同时到达。

为什么第一版用线性插补就够：上位机按 ≤250 ms 从五次多项式轨迹上采节点，并且已经检查过弦长误差（笔尖 ≤0.15 mm）和段间加速度。更高阶的插补要多传或多算导数，收益不大。

数值范围：轨迹参考的乘积最大 2500 步 × 500000 µs，用 `_Static_assert` 保证放得进 int32，中断里不需要 64 位除法。PTP 的时间律每 1 ms 只算一次，可以用 64 位；慢速长距离移动会超过 89 s（uint32 在 48 MHz 下能计的时长），所以计时器用了 64 位。

### 5.2 误差拆成“已知部分 + 实测部分”

直接写 `e = ref − 编码器` 有三个问题：编码器每 1 ms 才有一帧；单位是 LSB，方向要回零后才知道；帧在前台读，中断里多字段读取不原子。

所以拆开写：

```
e = ref − measured = (ref − cmd) + (cmd − measured) = (ref − cmd) + lag
```

- `cmd` 是步计数器，中断自己维护，任何时刻都精确；
- `lag` 是一个 32 位量（M3 上单字读写是原子的），由前台每帧更新一次。它用帧**开始时**的指令快照计算，所以帧传输期间多发的步不会被算成误差。

这样 10 kHz 的中断和 1 kHz 的采样就解耦了。方向换算复用点动保持用的同一个 `jog_enc_sign()`。

### 5.3 传感器延迟补偿

AS5045 慢速模式的输出晚于转子约 384 µs。速度为 v 时，这会让 lag 多出 v·τ（5000 步/s 时约 2 步，正好一个死区宽）。所以误差里扣掉 `v_cmd · τ`。原来开环的跟随检查（`slip_axis()`）也做了同样的补偿。

### 5.4 控制律：速度前馈 + 比例，不加积分

`v = v_ff + clamp(Kp·e)`。

- 正常运动由前馈完成，反馈只处理扰动。
- 步进电机的扰动基本是“一次性丢了 N 步”，相当于位置上的阶跃。速度到位置本身是积分环节，所以 P 就能把阶跃误差收敛到 0，不需要 I 项。加 I 项反而会在纠偏限幅饱和时积分饱和，在死区附近形成极限环。
- Kp 起始值 30 /s，带宽约 5 Hz。1.4 ms 的总延迟在这个带宽下只吃掉约 2.4° 相位。实际上限由编码器量化决定（1 微步 ≈ 2.56 LSB），需要上台架逐步加。

### 5.5 四道限幅 + 带回差的死区

| 限制 | 起始值 | 理由 |
|---|---|---|
| 纠偏速度 | 1000 步/s（20%） | 大误差时不让纠偏抢光速度余量 |
| 纠偏加速度 | 20000 步/s² | **只限修正量，不限前馈**。前馈的段间跳变已经被上位机和 `traj_push()` 按加速度上限校验过；连前馈一起限，会在每个节点交界人为制造滞后 |
| 总速度 | 5000 步/s | 与开环一致，也保证编码器多圈解包不歧义 |
| 禁止逆参考反向 | — | 参考向前走时不往回发步，最多停下等。这样编码器噪声和齿隙不会让 DIR 来回抖 |

**死区带回差**：|e| 超过 2 步才开始纠偏，开始后一直纠到 e = 0。到点判定也要求两轴都“不在纠偏中”。为什么这样做见 §7.3。

### 5.6 发步：每轴相位累加器（NCO）

| 方案 | 结论 |
|---|---|
| 沿用 DDA | 两轴步数比例锁死，不能单独追。否决 |
| 每轴算“下一步时刻”，定时器按最近一步唤醒 | 脉冲时刻最精确，但速度每 1 ms 都在变，两轴调度会很复杂 |
| **固定 10 kHz 节拍 + 每轴累加器** | 采用 |

累加器的细节：

- `acc += v·dt`，满一步发一步；
- `dt` 用 SysTick 实测，中断延迟不会变成位置漂移；
- 单拍 dt 封顶 1 ms，累加器封顶 2 步：中断被推迟后不会一口气补发一串脉冲，补不回的差距交给位置环（所以位置环必须能纠到 0，见 §7.3）；
- 换向时清零相位，防止换向后的第一步提前发出；
- 5000 步/s 时每 2 拍一步，抖动 ≤100 µs，DRV8825 完全能接受。

脉冲走原来的 `pulse_axes_try()` → `jog_step()` → UDB 一次性 PWM，所以限位、关节范围、nFAULT、使能检查一个都没绕开。

### 5.7 到点：按实测判定，再重新对齐计数器

- 运动结束后进入保持：参考停在终点，继续纠偏；
- 两轴连续 20 ms 都在死区内并且都不在纠偏中，才算到点；1 s 内到不了就停机；
- 前台再等 50 ms，按**编码器实测**和目标比较（限值沿用 228 LSB）。原来的判据“计数器 == 目标”在补过步以后不成立了；
- 然后**重新对齐计数器**：在死区内就把计数器设为目标，否则设为实测，同时把指令重置为实测（点动保持也是这样做的）。为什么要这样：后续的关节限位和“下一条轨迹必须从起点开始”的检查都依赖计数器代表真实位置，而后者要求计数器精确等于起点。

日志 `POSLOOP done: miss=终点误差 peak=最大跟踪误差 slip=丢了又补回的步数`。

### 5.8 安全

- 新增：跟踪误差 > 128 步就停机（等于原来开环的 328 LSB 停机线）；保持超时停机；停机时打印 `POSLOOP stop` 现场快照；
- 不变：心跳租约、前台卡死检测、硬件看门狗、nFAULT/限位引脚中断直接关断 PWM、关节范围、编码器失效停机、禁止开环降级。

### 5.9 构建开关

- `POS_LOOP` 默认 1，构建号带 `-posloop`（放在 `-enccomp-TESTDROP` 前面，因为补充实验按构建号结尾匹配固件）；
- `POS_LOOP=0` 保留原开环 DDA 执行器，代码和回归测试都还在；
- 闭环要求 `HW_EVT=1` 和两路编码器（`ARM2_ENCODER_FEEDBACK=1`），否则编译直接报错；只有一路编码器的构建必须是开环。

## 6. 验证方式

用项目已有的整机 C 仿真：真实的 `main.c`，加上模拟的 GPIO、编码器、SysTick、EvtTimer、UART、Flash。测试按构建分了几套：

| 构建 | 跑什么 |
|---|---|
| 交付配置（闭环） | 基础用例：点动、回零、链路、存档等 |
| 闭环 + 解锁 PTP | 全部 PTP/轨迹/模糊测试用例，以及新增的闭环用例 |
| 开环 `POS_LOOP=0` | 原 DDA 执行器的全部回归（精确步数、到期时刻、中断事件表） |
| 单编码器（开环） | 可选 arm2 编码器的配置 |

有 42 个用例只在开环构建里跑：它们断言的是 DDA 的内部细节（`seg.done`、精确脉冲数、到期时刻），闭环本来就该改变这些，每类都有对应的闭环用例替代。模糊测试有一条规则“计数器变化 = 电机实际变化”，闭环到点时的重新对齐是有意违反这条规则的，所以为它加了明确的例外。

新增闭环用例：

| 用例 | 场景 | 判据 |
|---|---|---|
| `ptp_posloop_axis1` | 单轴低速 PTP（200 步/s，arm2 不动） | 脉冲数恰好等于距离，终点误差 0，arm2 零脉冲 |
| `ptp_posloop_drop` | PTP 中途电机卡死 100 ms | 卡死期间的纠偏脉冲也丢了，松开后补回，转子到达目标 |
| `ptp_posloop_hold` | 终点保持刚开始时把转子撞回 6 步 | 正好多发 6 步，转子回到目标 |
| `ptp_posloop_dual` | 双轴 PTP | 两轴到达 |
| `traj_posloop_runs/drop/track` | 轨迹往返；中途丢步；永久卡死 | 到达 / 补回 / 停机 |
| `traj_posloop_host` | 上位机生成的真实矩形绘图（69 个节点，双轴同时运动） | 全程跟踪，终点在目标 |

判据都直接看**仿真转子的位置**，不只看固件自己的计数器。

## 7. 做的过程中踩到的问题（项目经历里最值得讲的部分）

### 7.1 闭环比开环少发 2 个脉冲，这是对的

往返轨迹在掉头点的误差只有 1 步，落在死区里；而“禁止逆参考反向”又不允许为了这 1 步再往前追。所以每个转角最多被削掉一个死区，终点不受影响。

结论：测试判据应该是“终点误差”，不是“脉冲数相等”。

### 7.2 丢步测试“没有补步”，问题出在测试本身

第一次让电机卡死的那段时间恰好跨过了参考的掉头点：电机还没到峰值，参考就回头了，所以环路直接跟回去，本来就不需要补步。逐毫秒打印 lag、误差和速度后确认符号是对的。

教训：**扰动要放在参考单调的区间，否则“没补步”也可能是正确行为**；判据要直接看转子位置，不能只看固件自己的计数器。

### 7.3 普通死区让运动停在死区边缘

单轴 PTP 第一次跑，终点差了 2 步（正好一个死区）。原因是两件事叠加：

- 发步累加器为了防止补发脉冲串会丢掉被推迟的中断时间（仿真里中断是成块调度的，所以更明显），在匀速段积累出 −2 步的滞后；
- 普通死区 |e| ≤ 2 时完全不纠偏，所以这个滞后一直带到了终点。

改成**带回差的死区**（超出才启动，启动后纠到 0）后，脉冲数精确等于距离，终点误差 0。这个问题如果上了真机，任何中断延迟都会留下同样的残差。

### 7.4 换算截断会吃掉一步

终点受扰用例被撞回 6 步，只补回 4 步。原因也是两件事：

- LSB → 微步用了截断（6 步 = 15.4 LSB → 5 步）；
- 到点判定只看“误差在带内”，纠偏还没结束就判了到点。

改成四舍五入（中断里的 lag 和前台的到点检查共用同一个换算函数），到点再要求“没有轴在纠偏”后，正好补回 6 步。

### 7.5 卡死时脉冲数远多于距离，也是对的

356 步的移动发了 427 个脉冲。卡死期间环路一直在纠偏，这些纠偏脉冲也被卡住的电机吃掉了，计数器比转子多走了 67 步。松开后转子按参考跟上，到达目标。真实卡死时有 128 步的跟踪误差停机兜底。

### 7.6 结束时的节点下标

保持阶段最初把节点下标退回到最后一个节点，和开环“结束时 index == count”的约定冲突，上位机状态和已有测试都依赖这个约定。保持阶段其实不读节点，所以改回一致。

## 9. 项目经历要点

可以按岗位挑着用。所有数字都来自仿真，有台架数据后替换。

**一句话版**：在 PSoC 5LP 上为双轴步进机械臂设计并实现电机轴位置闭环（参考插补 + 速度前馈 + 比例反馈 + 每轴独立相位累加器发步）。硬件、上位机和通信协议都不变；用整机 C 仿真验证了丢步补偿、终点抗扰和双轴绘图跟踪。

**展开版**：

- **架构**：把轨迹执行从“开环 DDA 按比例分配脉冲、编码器只报警”重构成“时间参考 + 编码器闭环”。双轴共用轨迹时钟：绘图走节点间分段线性插补，单点移动走梯形时间律，两者共用同一个控制器和发步器。
- **反馈设计**：把位置误差拆成“步计数器给出的精确开环部分”和“编码器测得的滞后部分”，从而把 10 kHz 发步中断和 1 kHz 编码器采样解耦，并补偿传感器 384 µs 的输出延迟。
- **控制律**：速度前馈 + 比例反馈。论证了步进系统的扰动是位置阶跃，所以不需要积分项，也避开了积分饱和。纠偏设了四道限幅（只限修正量，不限前馈），死区带回差。
- **实时发步**：每轴独立的相位累加器。用 SysTick 实测 dt 消除漂移，补发封顶防止脉冲串，换向时清相位。取代了两轴步数比例锁死的 DDA，使丢步的轴能单独追回。
- **安全与状态一致性**：按编码器实测判定到点，并重新对齐计数器；新增跟踪误差停机和保持超时停机；原有的心跳、硬件看门狗、引脚中断关断 PWM 等保护全部保留。
- **验证**：在已有的整机 C 仿真（真实固件 + 模拟外设）上，把开环和闭环拆成独立构建分别回归，新增丢步、卡死、终点受扰、真实绘图轨迹用例。过程中定位并修正了普通死区导致的终点残差、LSB 换算截断、到点判定过早等问题。

**面试时可以展开讲的点**：

- 为什么不用 PID：扰动形态 + 积分饱和；
- 为什么限幅只限修正量：前馈的加速度已在规划层校验过，再限一次会制造滞后；
- 为什么用固定节拍 NCO，而不是“算下一步时刻”：两轴独立变速，调度简单；
- 死区为什么要回差：§7.3 的现象和根因；
- 怎么证明闭环真的在补步：直接看仿真转子位置，以及扰动放在参考单调区间（§7.2）。
