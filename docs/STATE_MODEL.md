# 固件运行状态模型

本页把 `DRV8825.cydsn/main.c` 里分散的标志位整理成一张表：固件有哪些工作模式、哪些事件会改变它们、每种停止之后驱动器和坐标参考处于什么状态。**以源码为准**；发现不一致时先改源码或本页，不要两边各说各的。

下面第 4 节的约束由 `tests/test_stage1.py` 的 `fuzz_*` 用例在离线仿真里逐毫秒检查（随机事件序列，每个种子 6000 步）。它证明的是“固件逻辑自洽”，不是“实机一定这样”。

当前 v9 交付默认 `ARM2_ENCODER_FEEDBACK=0`，arm2 按指令计数且不要求编码器/方向；arm1 反馈保持必需。启用 arm2 反馈的构建才执行两路健康与方向检查。人工参考在默认模式可直接建立，无自动运动。

## 1. 模式

一个时刻只处于下表中的一种运动模式（“未使能”时全部为空）。

| 模式 | 源码判据 | 进入 | 离开 |
|---|---|---|---|
| 未使能 | `g_motionEnabled == 0` | 上电；任何停止 | 使能帧（type 7 / 键 C）成功 |
| 使能·空闲 | 已使能，`g_home.phase == HOME_IDLE`，`!g_ptp.active`，两轴 `want/moving == 0` | 使能成功；各运动结束 | 下面任一运动，或停止 |
| 点动 | `g_arm1.want/moving` 或 `g_arm2.want/moving` 非 0 | 心跳帧 type 6 的按键掩码非 0 | 掩码为 0（减速停），或停止 |
| 回零 | `g_home.phase` 为 RELEASE / BACKOFF / FAST / SLOW / SETTLE / STRAIGHT / STRAIGHT_SETTLE | 回零帧（type 8 / 键 R） | 走完 STRAIGHT_SETTLE 得 `HOME OK`，或停止 |
| PTP 单点 | `g_ptp.active`：1 运动，2 稳定检查 | PTP 帧 type 1 被接受（需要有效参考） | 到位检查通过，或停止 |
| 轨迹 | `g_traj.state`：0 空，1 上传中，2 就绪，3 运行（此时 `g_ptp.active != 0`），4 完成 | BEGIN(2) → 节点(3) → RUN(4) | 完成，或停止；点动键会清空上传 |

**坐标参考**（`g_ptp.reference`）不是模式，而是一个可以独立存在的属性：

- 来源：`referenceSource == 1` 开关回零；`== 2` 操作者确认的人工伸直零位（type 5）。
- 有效时必有 `g_homed1 && g_homed2 && g_directionKnown`。
- 每次作废，`g_ptp.epoch` 加一；上位机凭代次变化知道参考已失效。作废发生在：任何停止、使能、回零开始、人工建参考、参考有效时按下点动键（这一种只作废参考，`homed` 标志保留）。

## 2. 事件

带序号的帧（type 1…10）都先要求 CRC 正确、代次等于当前代次；type 1…5 用 PTP 序号，type 6…10 用控制序号，序号必须大于上一个已接受的，载荷完全相同的重发只重复回执、不重复执行。下表只列各自额外的前提。

| 事件 | 前提（不满足则拒绝并写日志，状态不变） | 结果 |
|---|---|---|
| type 6 心跳/按键 | 序号、代次、CRC 正确（代次过期的心跳仍续租约但不执行按键） | 续 250 ms 租约；使能且空闲时应用按键掩码；有参考时按键作废参考，PTP 运动中按键则停止 |
| type 7 使能 / 键 C | 当前未使能；最近一次心跳按键为空且租约有效；已松开按键；nFAULT、P0[4] 无效；编码器有效 | 两轴驱动上电，位置计数清零，进入“使能·空闲”，无任何自动运动 |
| type 8 回零 / 键 R | 已使能；编码器有效；心跳空闲；轴静止；无回零/PTP；输入正常 | 作废参考，进入回零；期间任何点动键即停止 |
| type 5 人工参考 | 已使能；arm1 编码器有效（`ARM2_ENCODER_FEEDBACK=1` 的构建还要求 arm2 编码器有效、方向已由回零识别）；空闲；心跳空闲；轴静止；输入正常且回零开关未触发；载荷全 0 | 当前姿态定义为 q1=q2=0，建立参考（来源 2），不动 |
| type 1 PTP | 参考有效且代次一致；序号递增；两轴已建零；目标在关节范围内；速度 20…4000；起点与编码器一致 | 进入 PTP |
| type 2/3/4 轨迹 | 同上，并要求起点在当前位姿、节点顺序/时长/速度变化合法 | 上传→就绪→运行 |
| type 9 范围 | 仅在**未使能、无参考、无运动、无回零、无缓存轨迹**时接受，且 `axis`/数值合法 | 更新关节范围 |
| type 10 速度/加速度 | `axis`/数值合法；无回零、两轴静止（含停稳）、无 PTP/轨迹运行或上传。**已使能、有参考也可以**（`LINK rates_live=1`） | 更新速度/加速度；设备里缓存的轨迹按旧速度检查过，数值变了就丢弃（`TRAJ_STATE state=0`），要重新上传；零位参考不变 |
| 原始 `0x79` 停止 | 任何时候 | 见第 3 节“operator stop” |
| 租约超时 | 使能后 250 ms 内没有有效心跳 | 停止（DEADMAN） |
| 硬件事件 | nFAULT、P0[4] 全局限位、回零/NPN 开关在不该触发时触发、编码器丢失/跳变/跟随误差 | 停止，原因见第 3 节 |

## 3. 停止：原因 → 结果

所有停止都经过同一个函数 `stage_stop()`，**它做的第一件事是打印一行 `FAULT_SNAPSHOT`**（停机瞬间的阶段、位置、编码器误差、输入、心跳年龄，见 PROTOCOL 第 5 节），之后才清状态；上位机把它和停机前 15 秒的遥测一起存成 `fault.json` / `pre_fault.csv`。快照只陈述已知事实：驱动器 nFAULT 一律记为“原因待诊断”。

停止函数的其余部分：两轴点动状态清零，回零/PTP/轨迹清空，`g_motionEnabled = 0`，`homed1 = homed2 = 0`，参考作废（代次加一），并要求“先松开按键、再显式使能”。区别只在驱动器：

| 停止原因（日志 `STOP:` 之后的文字） | 驱动器 | 说明 |
|---|---|---|
| `operator stop`（原始 0x79、Space/Esc、主机断开） | **断电**（EN 拉高，无保持力矩） | 唯一由操作者触发的停止 |
| `DRV8825 nFAULT…`、`PTP nFAULT`、`HOME nFAULT`、`ENABLE hardware fault/limit` | **断电**，并锁存 `g_jogFaulted` 直到下次使能成功 | 驱动器故障 |
| `DEADMAN host heartbeat timeout` | 保持通电 | 通信类：主机 250 ms 内无有效心跳 |
| `UART receive error/overflow…` | 保持通电 | 通信类：帧错误/溢出/校验错误，缓冲命令丢弃 |
| `P0[4] global limit` | 保持通电，锁存 `g_limitStop` | 限位输入有效；清除后再使能 |
| `encoder lost…`、`jog/HOME/PTP encoder following error`、`PTP start encoder mismatch`、`PTP final position mismatch`、`hold position lost` | 保持通电 | 编码器与指令位置不一致 |
| `PTP limit/home sensor`、`PTP time/joint limit`、`HOME …`（传感器、时间、行程、方向） | 保持通电 | 运动中触发了不该触发的传感器或超时/超范围 |
| `jog key pressed during PTP/HOME` | 保持通电 | 运动中收到点动键 |
| `trajectory timing overrun`、`PTP heartbeat/reference lost` | 保持通电 | 轨迹/参考失效 |

“保持通电”指驱动器仍带电流锁住转子，**不表示机械上不会被外力推动**；停止后一律要重新建立参考，不能沿用停止前的坐标。**没有独立于固件的实体急停**：驱动器断电不等于切断 VMOT。

## 4. 自动检查的不变量

`fuzz_run()` / `fuzz_invariants()` 在每个仿真毫秒之后检查（种子固定，可复现；失败时打印种子和步号）：

1. 未使能时：回零、PTP、轨迹运行、参考、`homed1/2` 全部为空。
2. 回零与 PTP 互斥；PTP 或回零进行时两轴没有按键意图。
3. `g_traj.state == 3` ⇒ `g_ptp.active`；`g_ptp.active` ⇒ 有参考且已使能。
4. 有参考 ⇒ `homed1 && homed2 && directionKnown`；空闲时两轴计数在关节范围内。
5. 一个毫秒内若发出了步进脉冲，则该毫秒开始时必须已使能，且当时 nFAULT / P0[4] 均无效。
6. `g_ptp.epoch` 和 `g_controlSequence` 不会减小。
7. 原始 0x79 之后必须已断使能且两轴 EN 为高。
8. 位置记账：一个毫秒内，固件的两轴位置计数变化等于模拟电机实际走的步数（回零改写计数的那一毫秒、以及 arm1 被人为卡住的毫秒除外）。
9. 只要固件仍处于使能状态，两轴各自的跟随误差（指令位置与编码器之差）就小于 `SLIP_FAIL_LSB + 64`——电机被卡住时，固件必须在越界前停止。

另外，`tests/test_stage1.py` 的定向用例分别覆盖各条停止原因、UART 错误、租约、代次、上传重试等。

## 5. 已知缺口（不是遗漏，是尚未决定或无法离线验证）

- 通信类停止也会作废参考，操作者每次都要重新回零或人工确认伸直；是否在“驱动器仍通电”的通信类停止后保留参考，需要另做安全决定（参考保留后坐标可能已被外力改变，且上位机依赖代次判断参考失效）。
- 快碰/慢碰回零阶段没有搜索上限，开关失效时只靠操作者停止。
- 编码器只在电机后轴，检测不到减速箱回差；只有 arm1 有电机侧编码器（arm2 的尚未固定，默认不要求；`ARM2_ENCODER_FEEDBACK=1` 的构建要求两轴都有）；PTP/轨迹尚未实现连续误差纠偏控制律。
- 肘范围（电机 2 = q2 − q1）已由固件和上位机强制执行，但数值是暂定的 ±155°，不是实测机械行程，见 README“关节范围填写规则”。
- 以上模型只在仿真里验证过；实机行为（含真实 UART 时序）以实机日志为准，见 `tools/check-log.py`。
