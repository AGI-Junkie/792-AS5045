# v6 先跑通动作：放宽终点验收

> **历史记录**：记录当时那次交付的改动和验证，可能与当前源码不一致（版本目录、固件标识、坐标约定都已变）。当前说明见 [README](../../README.md)、[协议](../PROTOCOL.md)、[状态模型](../STATE_MODEL.md)；以源码为准。

当前包：`deliverables/stage2-workbench-v6-motion-first`。本次改变的是固件，须用 PSoC Creator 打开当前 `DRV8825.cywrk` Build/Program，或烧入本包 `firmware.hex`。只更新上位机不会改变终点容差。当前 600 起点速度的上位机可继续使用；本包也带完整 `host` 文件夹，保留按钮视觉反馈、分段发送和后台自动运行。

按用户要求，终点验收从 16 LSB（arm1 输出角约 ±0.035°）改为独立的 `PTP_FINAL_ERROR_LSB=228`（约 ±0.50°）。起点接近与整条图形结束共用该检查，因此两处同时放宽。旧精调算法的 `CL_NEAR_LSB=16` 不变，后续可独立调整终点验收参数。

这是一项动作联调容差，不表示已达到 0.5° 定位精度，也不是实测笔尖 XY 误差。两轴命令步数仍须精确到达目标；编码器须有效。运动中的 328 LSB 跟随停止阈值、250 ms 心跳、驱动故障、传感器、关节范围和超时保护保持。本次不追加自动纠偏或重试运动。

## 使用

1. 停止动作并关闭上位机，烧录本包 `firmware.hex`。
2. 运行本包或此前 600 速度的上位机，连接后读取状态；原始日志应出现 `PTP_CHECK final_lsb=228 follow_lsb=328`。仍无此行说明需要确认烧录文件与板上版本。
3. 使能并建立真实零位：人工确认前须将两杆实际摆直，也可完整回零。烧录重启后的旧参考不能沿用。
4. 图形参数检查并保存，抬笔移到起点；收到 `PTP done` 后可落笔上传并执行图形。完成日志会包含实际 `error_lsb` 与 `final_limit_lsb=228`，误差曲线与实验文件继续记录，不隐藏偏差。

当前 `(330,0)`、半径 `15 mm` 的圆通过全部规划范围检查。固件 q1 ±30°、q2 ±60° 临时范围未扩大；本次解决的是到位精度门槛，较大圆的工作区域需另行标定。

## 验证

实际 C 模拟先在旧 16 LSB 版本注入 +67 LSB，复现 `PTP final position mismatch`。修改后 +67、-53 与 228 LSB 可完成，229 LSB 仍被终点检查拒绝，328 LSB 仍被运动跟随保护停止，错误双轴命令计数也仍停止。另以持续 67 LSB 编码器偏差跑通主机规划的“起点接近 → 全部上传 → 图形运行 → 结束”，正常完成并保留参考。

构建脚本还运行完整主机自测、实际 C 保护回归及圆/直线/矩形规划路径模拟。构建与模拟不代表实机动作或精度验证；本次未打开串口、烧录或驱动电机。
