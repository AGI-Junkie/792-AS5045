# 阶段二 E：图形上传与连续执行

> **历史记录**：记录当时那次交付的改动和验证，可能与当前源码不一致（版本目录、固件标识、坐标约定都已变）。当前说明见 [README](../../README.md)、[协议](../PROTOCOL.md)、[状态模型](../STATE_MODEL.md)；以源码为准。

交付目录：`deliverables/stage2-execution-open`；固件 `stage2-v2`。已经接通直线、矩形、圆的上位机执行入口、逐包确认、完整缓存和双轴定时插补。按用户明确要求开放低速实机执行：`PTP_COMMISSIONED=1`，q1 ±30°、q2 ±60° 为临时软件范围，不代表已标定的机械范围。默认小圆为圆心 (340, 0) mm、半径 5 mm。此交付尚未烧录、未打开串口、未实机绘图验收。

## 操作

1. 用完整 `host` 文件夹内的 `TwoLinkCommissioning.exe`。旧 stage1-v3 / stage2-v1 仍可用对应基础控制，图形执行需要 stage2-v2。
2. 用 PSoC Creator 打开当前 `DRV8825.cywrk`，Build/Program，或烧入本目录 `firmware.hex`。本版不再等待标定解锁；连接后应看到 `PTP_STATE lock=0` 和 `min1=-3000 max1=3000 min2=-6000 max2=6000`。仍为 lock=1 表示板上是旧固件，单换上位机不能解锁。
3. 人工使能、完整回零，选择图形与分支并检查预览。先抬笔，点“低速移到轨迹起点”；这是关节空间点到点接近，途中不保证直线。当前位置必须与量化后的起点命令计数一致。
4. 等待到位，按需要手动落笔，再点“上传并执行图形”。固件在上传开始和执行开始各检查一次起点；起点不符立即拒绝，不会自行走到起点。
5. 上传期间不运动，每包等待对应序号、点数和参考代次的确认。全部点确认后上位机才发启动包。界面显示上传 / 执行进度，执行期间锁住参数编辑。Space / Esc、总停止和窗口失焦继续中止；不自动重试或续跑。

没有抬笔执行器的控制接口，本版不会自动抬落笔。错误、停止、断线后原点失效，须重新使能、回零。正常图形结束保留参考，可以选择下一条图形。

## 轨迹执行边界

- 采用整条预装，不依赖运动中的 USB 连续供点。最多 2048 点，每点 6 字节，缓存约 12 KiB；每段 50～500 ms，总时长最多 600 秒。当前主机按约 250 ms 采样，超容量会拒绝，不截断。
- 执行版本重新按低速上限规划：末端 5 mm/s、q1 2°/s、q2 1.5°/s，规划加速度 q1 2°/s²、q2 1.5°/s²；用户填写更低值时采用更低值。显示执行版本的独立时间，原来的播放与 CSV 仍是离线预览数据。
- 上位机和固件均按量化后的实际脉冲数逐段核对：每轴平均速率不超过 600 微步/s，相邻段速度变化按 800 微步/s² 检查，检查首段由静止起步和末段停下。矩形角点和终点插入 50 ms 无步进停留。
- 固件按段时间做关节线性 DDA，同一时间基准协调两轴，在普通采样点不重新跑点到点加减速。最小主轴脉冲间隔 1667 µs；落后段结束时间超过 20 ms 立即停止，不高速补发积压脉冲。
- 分段速度有微小跳变，这是低速弦线近似，并非速度 / 加速度连续的曲线控制。上位机每段检查 9 个位置的规划近似偏差 ≤0.15 mm（包含角度和脉冲量化）；这不是连续误差证明，也不是实测笔尖精度。高速、转角振动与负载能力必须由实机验证。
- 沿用编码器有效性 / 跟随误差、驱动故障、三路传感器、关节范围、250 ms 心跳和结束停稳检查。arm1 有电机侧编码器；arm2 只有命令计数，没有末端 XY 的实测误差。真实误差曲线与实验 CSV 尚待反馈采集和实机实验。

## 协议增量

沿用 [STAGE2_PTP.md](STAGE2_PTP.md) 的 17 字节、奇数 nibble、三份重复、CRC16 和 epoch/sequence 机制。首字节新增操作类型，旧 `01` 单点保留：

| 类型 | q1 / q2 字段 | 最后 uint16 字段 | 行为 |
|---|---|---|---|
| 02 | 首点百分之一度 | 总点数，含首点 | 校验起点并建立空闲上传缓存 |
| 03 | 下一点百分之一度 | 从上一点到该点的毫秒数 | 顺序追加；必须是已接受序号 +1 |
| 04 | 都为 0 | 0 | 全部点已收到且起点吻合才启动 |

所有节点逐包校验 CRC、范围、顺序、时间和脉冲速率。任一包被拒绝不更新序号 / 点数，上位机请求停止；3 秒无对应确认也停止。相同序号、相同内容重复到达只回复状态，不重复追加或重新启动。普通 PTP 在上传 / 就绪期间拒绝；停止、重回零和点动都会清除缓存参考。

新增状态行：

```text
TRAJ_STATE state=3 count=100 total=100 index=21 seq=102 epoch=7
```

`state`：0 空、1 上传、2 收齐、3 运行（含最终停稳检查）、4 完成。`count/total` 含首点；`index` 为目标点下标，完成时等于 count。主机用该行确认轨迹包，不能用旧 `PTP_STATE` 代替节点确认。
