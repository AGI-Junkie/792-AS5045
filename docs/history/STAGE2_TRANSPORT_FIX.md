# stage2-v4：移动请求超时的通信修正

> **历史记录**：记录当时那次交付的改动和验证，可能与当前源码不一致（版本目录、固件标识、坐标约定都已变）。当前说明见 [README](../../README.md)、[协议](../PROTOCOL.md)、[状态模型](../STATE_MODEL.md)；以源码为准。

最新实机日志 `stage1-20260924-223020-984.log` 显示人工零位确认成功，但移动请求 seq=2、6 均未被固件接受：接收序号停留在 1、5，active=0，随后上位机 3 秒超时停止。目标 q1=-21.95°、q2=44.37° 在当前软件范围内；这一阶段没有限位、驱动故障或运动拒绝报告。

源码检查发现：收到结束符时，不完整的运动包会被静默丢弃；上位机只发送一次完整包。丢失一组重复字节的模拟可重现相同现象，但不能据此认定现场丢字节的具体原因。日志中的 late/rejected 是软件 UART 接收计数，不等于已确定的 USB 故障。

## 修改

- 固件将不完整包、CRC 错误、帧超时记录为 `PTP RX dropped:`，仍不执行不完整或损坏的数据。
- 新上位机连接 stage2-v4 时，在请求后约 1 秒、2 秒各允许重传一次，总计最多 3 次；原有 3 秒总期限不延长。人工零位、单点移动、轨迹节点和运行指令共用这个逻辑。
- 重传保持完全相同的序号、epoch 和数据。固件重复包只回状态，不重复移动、清零或添加节点。
- 接受回执、实际拒绝、停止、故障或断开会取消待发送请求。停止后的旧包不能恢复运动。250 ms 心跳、编码器及输入检查保持原样。
- 旧固件不启用整包重传；本次应同时更新上位机和固件。

## 使用

1. 用 PSoC Creator 打开 `DRV8825.cywrk`，Build / Program 当前工程；也可用编程器烧录本交付的 `firmware.hex`。
2. 关闭旧上位机，运行同目录 `host/TwoLinkCommissioning.exe`，保留完整 host 文件夹。连接后日志应显示 `STATE fw=stage2-v4`。
3. 人工摆直 → 使能 → 人工确认伸直零位 → 低速移到轨迹起点。正常应出现 `PTP accepted`、相同 seq 的 `PTP_STATE active=1`，完成后 active=0。
4. 首次完整轨迹使用默认圆心 (340,0) mm、半径 5 mm。此前圆心 (280,0)、半径 50 mm 的起点可达，但整圆超出当前 q1 ±30° / q2 ±60° 软件范围。
