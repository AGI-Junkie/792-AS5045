## 本次报警

本机 `stage1-20260927-194402-036.log` 显示：19:50:46.194 起点移动 `PTP done seq=16`，实验结果为 complete；19:50:55.020 开始上传 242 点图形，传到第 19 点后，在 19:50:56.170 报 UART 接收错误。图形尚未执行，停止时 key_age_ms=20，rx_overflow=0，rx_error 从 1 增至 2。19:49:54 的人工零位请求也出现过相同接收错误。

这是 UART 的 Break、校验或停止位错误之一，不能从旧日志区分具体位。生成的 UART API 不会把普通 FIFO 状态误认成错误，静态波特率也在合理误差内。现有证据不能确认 USB 桥、线路干扰或持续字节流中的哪一项是物理触发原因；没有把该报警归因于轨迹范围或心跳。

## 已改动与复测

硬件 UART 模式每次接收计时器回调最多发送 8 字节，约每 40 ms 一段，36 字节帧约 160～200 ms 发完，段间继续处理心跳与接收。保持现有 CRC、序号和参考代次确认、三次重试及 250 ms 心跳保护；未完整发出的帧不会被重试插入重复数据。上传会比原来的整帧模式慢，电机速度及路径不因此改变。

这种分段发送是针对持续字节流的兼容性调整，需实机确认能否消除本次触发。确认当前姿态和真实参考后，按原流程移到起点并上传；若再次报错，程序仍停止并作废参考，不能继续使用报警前的零位。日志自动保留，不需要手工发送。

人工确认点击后立即显示“正在确认”并禁用重复提交，按钮下方显示等待文本；只收到有效序号、下一参考代次、ref=1、未锁定和空闲回执才显示持久的“已确认”。拒绝、超时、断开或零位失效会显示明确原因，无弹窗。正常状态轮询不会闪掉成功反馈。切换窗口或最小化仍允许自动动作继续，手动点动失焦释放。

## 可选诊断固件

本包 `firmware.hex` 只需在分段上位机仍报 UART 错误、需要辨别错误位时烧录。新增 `UART RX fault: flags=... sw_overflow=... break=... parity=... framing=... overrun=...`，在退出临界区后记录；接收错误仍会丢弃缓存并停止。没有吞掉错误或放宽保护。

诊断固件采用已完整回零成功的速度：快碰 600、慢碰 400、arm1 伸直 800、arm2 伸直 600 微步/秒。此前 `stage2-workbench-v6-parameters/firmware.hex` 的 arm2 伸直 800 提速试验保留在原包；本包不混入这项未实机验证的提速。

## 离线验证边界

实际 C 模拟覆盖分段传输的单点、轨迹上传和运行，以及 framing、Break、校验、硬件和软件溢出停止保护；上位机自测覆盖分段发送顺序、写入失败不丢队列、部分发送不重试，以及人工确认等待、真实成功、拒绝、超时、断开和参考失效。完整结果见本包构建报告和测试日志。模拟 UART 不复现真实线路干扰，未连接串口、烧录或驱动电机，现场结果仍须复测。
