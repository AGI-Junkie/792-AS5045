# 2026-10-09 上位机实验结束时的心跳停顿

## 现场记录

会话 `stage1-20261009-142827-284.log` 在 14:32:46.774 报告点移 `PTP done seq=2`。随后保存 `20261009-143241-179-point-2`，14:32:47.834 上位机报告 UI 租约间隔 974 ms，14:32:47.863 报告实际心跳间隔 788 ms。

固件触发时的 `FAULT_SNAPSHOT` 是 `phase=idle traj=0 idx=0/0`、`hb_age_ms=251`，原因 `DEADMAN host heartbeat timeout`；RX 错误和溢出均为 0，编码器状态和校验正常。这一记录尚未发出图形上传报文，停顿出现在点移结束后的保存/刷新阶段。

## 复现及修改

`FinishExperiment()` 在 WPF 界面线程调用 `RefreshRecentRuns()`，同步枚举并解析历史记录。当前现场目录有 109 条记录。用旧上位机程序集及隔离的 2000 条历史记录目录重放真实结束方法：调用约 229–240 ms，界面心跳间隔约 249–251 ms，超过 200 ms UI 租约。分段测量中，档案刷新约 159 ms，文件收尾约 1 ms，布局无明显耗时。该压力用例证明同步扫描可以触发同类超时，不代表测出了现场 974 ms 停顿的每一个分量。

改为后台扫描，回到界面线程更新最近记录；记录文件正常收尾，收藏缓存保留，旧扫描结果不能覆盖较新的刷新。相同离线重放的实验结束调用约 17 ms，界面心跳最大间隔约 32 ms。未修改 200 ms UI 租约、250 ms 固件保护、串口节奏或固件代码。

新增 `ExperimentFinishHeartbeatSelfTest()`，用真实的结束方法及 5000 条隔离历史记录，检查界面心跳低于租约截止时间，同时确认实验摘要和最近记录仍可用。该检查纳入上位机自检；旧上传回放未经过真实记录收尾，因为 `selfTesting` 跳过了 `StartExperiment()`，所以此前闸门漏掉了这一场景。

候选版完整上位机自检结束，新检查测得结束调用 8.5 ms、界面间隔 36.9 ms，摘要和最近记录保留。原有 383 节点上传回放一次测到 203.8 ms UI 租约间隔，现有重试机制在后续一次通过，并将首次警告保存在 `out/upload-heartbeat-diagnosis/self-test/heartbeat-tests.txt`；不能把自检成功理解成消除了全部调度波动。
